# otsdaq Lite Architecture

## What is OTS_LITE?

When the environment variable `OTS_LITE=1` is set, otsdaq builds without
XDAQ, artdaq, ROOT, and other heavy dependencies. The CMake preprocessor
define `OTS_LITE` gates code at compile time (`#ifdef OTS_LITE` /
`#ifndef OTS_LITE`).

## Key Repos (all on branch `feature/ots-lite`)

| Repo | Role |
|------|------|
| otsdaq | Core: supervisors, FE framework, XdaqLite stand-ins, `ots` script |
| otsdaq-utilities | WebGUI, MacroMaker, ConfigurationGUI, Visualizer, Console |
| otsdaq-components | FE interface plugins (FEOtsUDPTemplateInterface, etc.) |
| otsdaq-demo | Demo config, `ots-quick-lite-start.sh` installer, emulator |

## XdaqLite

Real XDAQ classes are replaced by lightweight stand-ins:

- `otsdaq/XdaqLite/` — Application, ApplicationStub, SOAPMessenger, etc.
- `otsdaq/XdaqLite/ots_lite_main.cc` — the executive (replaces xdaq.exe)
- `otsdaq/XdaqLite/ArtdaqLite.cc` — replaces artdaq's configureMessageFacility

### ArtdaqLite.cc caveat

`artdaq::configureMessageFacility()` in the lite build ignores
`ARTDAQ_LOG_FHICL` / `OTSDAQ_LOG_FHICL`. It only creates hardcoded "cout"
(if useConsole=true) and "file" (if ARTDAQ_LOG_ROOT set) destinations.
The UDP and OTS-type MF destinations from `MessageFacilityGen.fcl` are
never created in lite.

## Build Commands

After `source setup_ots.sh`:

| Alias | What it does |
|-------|-------------|
| `mb` | Incremental build (cmake --build + --install for each package) |
| `mz` | Clean build (wipe build dirs, re-cmake, build, install) |
| `mz_uc` | Ultra clean (also rebuilds dependencies from scratch) |

Never use raw cmake commands. Never build in user areas — only edit in `dev-srcs/`.

## Launching

```bash
ots --wiz    # first-time wizard mode
ots          # normal run
ots -k       # kill (alias: kx)
```

Scripted start/stop (an agent has no terminal to answer prompts):

```bash
cd <lite-area> && . setup_ots.sh          # sets PATH and the OTS_*_UDP exports
echo Y | ots -k                           # -k asks "Are you sure ...? [Y/N]"; no answer aborts it
nohup ots > /tmp/ots_run.log 2>&1 &       # ots returns once the system is up
sleep 25; ss -ulnp | grep -E ':2010|:2011|:2014'   # UDP ports bound = ready
```

`ots` prints the web URL (`http://<host>:2015/urn:xdaq-application:lid=200/`) when
ready. It never starts `ots_udp_hw_emulator`. The soft kill (`ots -k`) leaves a
running emulator alone, so it survives restarts; the hard kill (`ots -K`, also
`killall -9`s art/artdaq processes) stops it, so restart it by hand afterwards.

## setup_ots.sh

Generated by `ots-quick-lite-start.sh`. Sets PATH, LD_LIBRARY_PATH, 
CET_PLUGIN_PATH, TRACE, and user-chosen exports like:

```bash
export OTS_MACROMAKER_UDP_PORT=2011
export OTS_MACROMAKER_UDP_IP=127.0.0.1
export OTS_CONFIG_UDP_PORT=2010
export OTS_CONFIG_UDP_IP=127.0.0.1
```

These are user-decided — not added by default in the installer.

## TRACE

TRACE shell functions (`tlvls`, `tshow`, `tonM`, etc.) come from
`trace_functions.sh`. In lite, `setup_ots.sh` must source it explicitly
(Spack did this automatically in the full install):

```bash
[ -f $SCRIPT_DIR/local/install/bin/trace_functions.sh ] && source $SCRIPT_DIR/local/install/bin/trace_functions.sh
```

## OTS_LITE Guards

When adding new code that uses ROOT, XDAQ, artdaq, or other missing
dependencies, wrap it:

```cpp
#ifndef OTS_LITE
// code that needs ROOT/XDAQ/artdaq
#endif
```

In CMakeLists.txt:
```cmake
if(DEFINED ENV{OTS_LITE})
  # lite link libraries
else()
  # full link libraries
endif()
```

Common things that need guards:
- ROOT types (TH1, TFile, TCanvas, etc.)
- `DQMHistosConsumerBase` and subclasses
- `RawDataVisualizerConsumer` (uses DataManager which needs full artdaq)
- Any `dynamic_cast` to types not compiled in lite
