# An isolated otsdaq installation for an agent, next to others on the same host

How to run an installation (for an agent's tests, a tutorial walkthrough, a second subsystem)
on a host where other installations run, without touching them: what separates two
installations, how to move the ports, what never to run, and how to stop only your own
processes.

## What separates two installations

| Shared on a host | Separated by | Tool |
|---|---|---|
| files | `USER_DATA` (Data directory) and `ARTDAQ_DATABASE_URI` (configuration store) of each install area | `setup_ots.sh` of the area |
| TCP ports | every context `Port` (the Gateway context usually `${OTS_MAIN_PORT}`), Wiz mode `OTS_WIZ_MODE_MAIN_PORT` | `isolate_ots_ports.py`, `setup_ots.sh` |
| UDP ports | Gateway remote control (`GatewaySupervisorTable` `PortForStateChangesOverUDP`), Configuration (`OTS_CONFIG_UDP_PORT`) and Macro Maker (`OTS_MACROMAKER_UDP_PORT`) remote controls, front-end interface/host/stream ports, data listeners and streamers, Console forwarding (`MessageFacilityTable`) | `isolate_ots_ports.py` |
| the hardware emulator | its UDP port (the FE's `InterfacePort`; 4000 in the tutorial data) | `emulator_ctl.sh` |
| processes | `ots -k` and the scripts below act only on processes whose command line holds this `USER_DATA` | `ots_mode.sh`, `emulator_ctl.sh` |

Two installations from the same tutorial data use the **same** ports everywhere: a copy is not
isolated until its ports move.

## Recipe

1. **A separate area.** Install one (`ots-quick-lite-start.sh` / `ots-quick-maxlite-start.sh` in a new
   directory), or reuse a scratch one. Its own `Data` and store come with it.
2. **Environment ports.** `setup_ots.sh` is regenerated by `mz_uc`, so set the ports in a small
   wrapper sourced instead of it (as `dev-ots-web/setup_area.sh` does):
   ```bash
   source "$(dirname "${BASH_SOURCE[0]}")/setup_ots.sh"
   export OTS_MAIN_PORT=3015 OTS_WIZ_MODE_MAIN_PORT=3015
   export OTS_CONFIG_UDP_IP=127.0.0.1 OTS_CONFIG_UDP_PORT=3012
   export OTS_MACROMAKER_UDP_IP=127.0.0.1 OTS_MACROMAKER_UDP_PORT=3011
   ```
3. **Table ports.** Start the area in Wiz mode (`ots_mode.sh wiz`: one process, only
   `OTS_WIZ_MODE_MAIN_PORT`), or in normal mode if nothing else uses its ports yet, then:
   ```bash
   ai_scripts/isolate_ots_ports.py                      # list ports, mark ones other processes hold
   ai_scripts/isolate_ots_ports.py --offset 1000        # preview the moved ports and their conflicts
   ai_scripts/isolate_ots_ports.py --offset 1000 --apply --accept-warnings
   ```
   It saves one new key each of the active Context and Configuration groups. Configure uses an
   **alias**: move it to the new Configuration key (`cfg_udp_set_alias.sh <alias>`), see
   `configuration-model.md`. Repeat for other Configuration groups the area uses.
4. **Restart twice** (context ports change the layout: `ots_mode.sh stop`, then `ots` twice), and
   start the emulator on the new port: `emulator_ctl.sh start <new InterfacePort>`.
5. **Check:** `isolate_ots_ports.py` reports `0 conflict(s)`, and every port shows `free` or
   `this installation`.

## Never, on a shared host

- `killall` of anything (`killall -9 xdaq.exe`, `killall -9 ots_udp_hw_emulator`): it reaches every
  installation of the user.
- `ots -K` (hard kill: every user's otsdaq processes on the host).
- `reset_ots_tutorial.sh` (it runs `killall -9 ots_udp_hw_emulator`). Use `switch_ots_tutorial.sh`.
- Editing another area's `Data`, store or `setup_ots.sh`; sending UDP to another area's remote
  controls (name the allowed addresses in the agent's first message: `agent-first-message.md`).

## Stopping only your own

| Stop | How |
|---|---|
| this installation's contexts | `ots -k` (asks; `echo Y \| ots -k`), or `ots_mode.sh stop` |
| this installation's emulator | `emulator_ctl.sh stop <port>` (only an `ots_udp_hw_emulator` of this user on that port) |
| a run | `ots_drive_udp_test <ip> <port> <fsm> Stop` / `Halt` |

## Verified

2026-11-14 on ots maxlite (5015/2016, Gateway UDP 2014, emulator 4000) next to the tutorial area
(3015) and the lite test area: `isolate_ots_ports.py` listed 18 table ports and 3 environment ports,
classified the area's own emulator and contexts as "this installation", found another user's
process on a proposed port (6010), and `--offset 1000 --apply --accept-warnings` saved and activated
new Context and Configuration keys (then reverted). `emulator_ctl.sh` started, refused and stopped
an emulator on a spare port without touching the one on 4000. Not yet done end to end: a second
area run in normal mode on moved ports.
